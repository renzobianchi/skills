# ds-ai-ready

Migrate an existing design system to shadcn, or start one from zero, so that agents can build with it. Tool-agnostic core in markdown, thin adapters for Claude Code, Codex, Cursor and Grok, and a manifest layout designed so component PRs never conflict with each other.

## Layout

```
core/
  rules.md              rules the agent applies on every component (model-invoked)
  traps.md              silent failures that masquerade as component bugs
  phases/               one file per phase: triage, foundations, kit, parity, component, cleanup, patterns
  templates/            ds.config.json, per-component manifests, ds-manifest.mjs, guard tests,
                        the project's own skill, RFC addendum
.claude-plugin/         plugin.json and marketplace.json (install as a Claude Code plugin)
adapters/
  claude/skills/        ds-rules (auto, generated), ds-migrate (/ds-ai-ready:ds-migrate <phase>), ds-patterns
  codex/AGENTS.md       Codex reads AGENTS.md natively
  cursor/rules/*.mdc    ds-rules fires by glob; ds-migrate by @-mention
  grok/AGENTS.md
scripts/sync-adapters.mjs regenerates the inlined ds-rules skill from core/
PLAYBOOK.md             the long-form reasoning behind every phase
```

## Install

Claude Code, as a plugin (the whole folder travels together, so `core/` is always next to the skills):

```
/plugin marketplace add /path/to/ds-ai-ready   # or the git URL
/plugin install ds-ai-ready@ds-ai-ready
```

For a checkout you are editing: `claude --plugin-dir /path/to/ds-ai-ready`. Skills are namespaced: `/ds-ai-ready:ds-migrate foundations`. `ds-rules` fires on its own for files under the namespace.

`ds-rules` ships with `core/rules.md` and `core/traps.md` inlined (generated by `node scripts/sync-adapters.mjs`; `check` mode fails when stale). Reason: a model-invoked skill cannot depend on reading a file outside the working directory, since headless sessions deny that read without a prompt. The phase skills read `core/phases/*` through `${CLAUDE_PLUGIN_ROOT}`; grant the Read once per session if asked.

Codex / Grok / Cursor read `core/` by path from the repo root, so vendor the package there as `ds-ai-ready/` (copy or git submodule). Then:

- Codex / Grok: copy the adapter `AGENTS.md` to the repo root (Codex also under the namespace folder).
- Cursor: copy `adapters/cursor/rules/*.mdc` to `.cursor/rules/`; edit the `globs` line if the namespace is not `src/next`.

## First run

1. `/ds-migrate foundations` writes `ds.config.json` (design tool, Code Connect on/off, tracker, primitives), scaffolds the namespace, installs manifests and guards, and writes the project's own rules skill.
2. Existing library: `/ds-migrate triage` first (usage scan, legacy map, token freeze).
3. Design owner runs `phases/kit.md`; each finished page flips to 🟢 and gets its manifest file as `kit-ready`.
4. `/ds-migrate component <key>` per component: one branch, one PR, self-review before a human reviewer, squash merge, wait for green publish.
5. `/ds-migrate cleanup`, then `/ds-patterns`.

## Why component PRs stop conflicting

Every PR used to edit one shared `parity.json`, one `PARITY.md`, one `LEGACY-MAP.md`. Each merge conflicted every other approved PR; each resolution was a push that dismissed an approval. Now: one manifest file per component (`parity/<key>.json`, `legacy/<Export>.json`), docs generated by `node scripts/ds-manifest.mjs docs` and guarded for equality, namespace index one export per line sorted. A component PR touches its own files only; approved PRs stay `CLEAN` after another merges.

## Config flags

| Key | Values | Effect |
|---|---|---|
| `designTool` | `figma` / `paper` | which bridge the kit-first audit uses; Paper forces `codeConnect: false` |
| `codeConnect` | bool | `<key>.figma.tsx` required and guarded per `parity` component |
| `tracker` | `linear` / `none` | issue creation and state moves per component |
| `primitives` | `base-ui` / `radix` | which state selectors are alive |
| `manifests.commitDocs` | bool | generated docs committed and guarded, or only rendered |
| `markers` | emoji | kit page lifecycle, default 🟡 → 🟢 → 🔄 |
