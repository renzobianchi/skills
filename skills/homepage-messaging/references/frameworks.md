# Frameworks

## Value Proposition Canvas (seven questions, four links)

For one persona and your product, in this order:

1. Who are you crafting the message for? (target customer)
2. What does the product let this person do? (capability; the product link: what the user would actually see and do)
3. When would someone need this capability? (use case; "the user is trying to…")
4. How does the customer currently carry out this use case? (current way, competitive or contextual)
5. What are the limitations of doing it this way? (the capability link: it should contrast drastically with the capability; this comparison is the core of the differentiation)
6. What is the underlying problem they run into? (the current-way link)
7. What is the outcome of doing it your way? (benefit; the problem link: it should directly oppose the problem)

Rules: capabilities stand out against the alternative's weaknesses; benefits remove the blockers to progress; each capability is tied to specific features; use cases are lead measures, not lag measures. Shortcut when there are many candidates: rank market activities by pain, rank features by wow factor, connect the most painful activities to the most compelling features.

## Problem framing

Pick a use case → select the capability → write the current way → list every possible framing of the problem → map each framing to the benefit it implies → choose the framing that resonates with the target audience, not the one you like most.

## Messaging House

Top half, minimum viable positioning: eight boxes (persona, company type, context, problem / category, capability, feature, benefit); fill at least one market box and one product box; that is the hero. Bottom half: three value propositions, the three arguments for using the product, each tied to a sub-use case; they can cascade (a value prop can open a page of its own).

## Messaging Stairs

The trust ladder in argument order: persona → using → alternative → encounters → problem → solved by → capability → powered by → feature → which drives → benefit. Show what the product does before what it changes; outcomes come last.

## The World's Clearest Homepage Template

1. Hero: position the product (what, who for, which use case); logos here.
2. Problem section: the struggling moment, in the champion's framing.
3. Solution intro: the category or the use-case anchor plus the differentiated capability.
4 to 6. Value propositions at the feature-set level, one section each: context → problem → capability → feature → benefit.
7. Proof and CTA.

Minimum viable website: three sections that together answer category, target customer, problem, capabilities, benefits.

### Post-hero section by situation

| Situation | Section type | Leads with |
|---|---|---|
| New or emerging category | How It Works | capability + feature |
| Horizontal product, several jobs | Use Cases | use case |
| Very mature category | Features | feature |
| Forced by stakeholders | Results | benefit, at the bottom |

### Homepage variations by audience

Single persona, single use case (the default); single persona, multiple use cases (use-case sections); multiple personas, single use case (pick one for the first scrolls, persona pages for the rest); multiple personas and use cases (hardest; prioritize, never itemize or summarize). Site structure: home, persona pages, use-case pages are the entrance paths; everything else is secondary.

## Hero templates

| Template | Shape | When |
|---|---|---|
| X for Y | `<category> for <persona>` + capability + feature | mature category, clear persona |
| Category differentiator | top one to three differentiating capabilities + product GIF | saturated market |
| How-to (Loom) | "Record and share <thing>" capability lead | PLG, one clear workflow |
| Networker (Calendly) | the use case as a sentence the reader already says | contextual anchor |
| Channel-changer (Rippling) | one page per persona | only with distribution to spare |

All six elements appear somewhere on the page; the choice is what to lead with.

## Stage of awareness → what to lead with

Problem unaware: the alternatives. Problem aware: the problem. Solution aware: capabilities. Product aware: features. The homepage is demand capture (capabilities); channels before the site are demand creation (problems).

## Persona translation

Users → use case; champions → problem; decision makers → outcomes; financial buyers → ROI; technical influencers → logistics. The homepage speaks to the champion.

## Copy pipeline

Draft 1, product marketer: arguments, narrative, outline (this skill). Draft 2, first real draft: expect the founder to re-litigate positioning here; send them back to the positioning doc, not forward. Draft 3, copywriter (`language-market-fit`). Two iterations, then ship. Stages of a page: product marketing → copywriting → design → CRO.

## Headline audit

List every headline in page order; tag each with its element; check the page against the counts (personas 1 to 2, problems 1 to 3, category exactly 1, capabilities 1 to 3, features 1 to 5, benefits 1 to 3); answer the four questions from headlines alone. Clarity test before any A/B test: a stranger reads the hero for five seconds and says what the product does and who it is for.
