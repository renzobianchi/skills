# Messaging elements

The shared vocabulary of the Fletch method. Every interview answer lands in one of these boxes; a doc that uses them consistently can be handed to `homepage-messaging` without translation.

## Market side

| Element | Definition | Test | Sloppy version |
|---|---|---|---|
| Target customer | Company type plus champion (the person whose job it is to fix the problem, senior manager to VP) | You can name the title and the kind of company | "SMBs", "businesses", "enterprise" |
| Use case | A functional activity a worker performs; a user scenario (context + problem) plus the product functionality that serves it | You could build an onboarding flow for it | An outcome ("grow revenue") or a why |
| Competitive alternative | How the target customer carries out the use case today: a product, a DIY stack, a manual process, an agency | Named specifically, one primary | "Legacy tools", "the old way" |
| Limitation | What the alternative cannot do or does badly, in a way that contrasts with your capability | Reads as the mirror of a capability | A general complaint |
| Problem (struggling moment) | The moment the limitation hurts, pointable on a calendar; a problem someone owns, feels and can act on | You can picture the meeting or the spreadsheet | A root cause ("data is siloed") |

## Product side

| Element | Definition | Test | Sloppy version |
|---|---|---|---|
| Product category | The shelf buyers already shop; exactly one per page | A buyer would type it into G2 | A category you want to own in the future |
| Capability | What the product lets the customer do; an input, tied to a feature | Verb plus object the user would actually do | "Operationalize your data" |
| Feature | The technical thing that makes the capability possible; a word or phrase | A screen or setting you could point at | A branded name |
| Benefit | The state change: more of something good, less of something bad; first-order, directly opposing the problem | Follows from the capability in one step | Fourth-order ("close more deals") |

## The chain

Persona → using → Alternative → encounters → Problem → solved by → Capability → powered by → Feature → which drives → Benefit.

Positioning = target customer + differentiation, where differentiation = product category (or use case, when the category is new) + how you solve the use case differently, backed by a feature. Messaging is which of those elements a given asset leads with.
